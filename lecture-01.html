Введение в Python

Как программа превращается в результат на экране, где писать и запускать код, какие данные хранит Python и как с ними считать.

После лекции вы сможете

  • объяснить путь программы от файла .py до результата и по сообщению интерпретатора определить вид ошибки;
  • запустить программу из файла, вывести данные функцией print() и прочитать ввод функцией input();
  • выбрать тип для значения, преобразовать его явно и не попасть в ловушки ссылок и вещественных чисел.

Программа, алгоритм, интерпретатор

Человек понимает смысл текста, но медленно и с ошибками считает. Компьютер выполняет миллиарды операций в секунду, но смысла не понимает вовсе. Программирование распределяет работу между ними: рутинный счет отдается машине, постановка задачи и смысл результата остаются человеку. В этом курсе машина будет считать GC-состав, частоты кодонов и искать мотивы в последовательностях.

Алгоритм — способ решения задачи, записанный словами, схемой или псевдокодом без привязки к языку программирования.

Программа — алгоритм, записанный инструкциями на конкретном языке для конкретного исполнителя.

Решение идет цепочкой «задача, алгоритм, программа, исполнение». Большинство ошибок появляется на переходе от алгоритма к программе: способ решения верный, а записан он неточно.

Программа хранится во внешней памяти (на диске) и переживает выключение компьютера. Чтобы заработать, она загружается в оперативную память, а команды выполняет процессор. Переменная x после x = 123 находится в оперативной памяти, а не в процессоре и не на диске. Поэтому при внезапной перезагрузке значения переменных теряются, а файл с программой остается.

Почему процессор не может выполнить файл .py сам?

Подсказка: процессор выполняет только свои команды. Похож ли на них текст, набранный в редакторе?

Процессор понимает только машинный код, а файл .py содержит обычный текст. Значит, между текстом программы и процессором нужен переводчик.

Машинный код — команды процессора в двоичном виде; они привязаны к архитектуре процессора и к операционной системе.

Писать машинный код вручную умеют немногие. Поэтому программу пишут на языке высокого уровня, например на Python, а программа-переводчик превращает ее в команды процессора. Отсюда практическое следствие: исходный текст на Python один для Windows, macOS и Linux, а машинный код для каждой системы свой.

Python интерпретируемый язык. У этого есть цена: часть ошибок проявляется только тогда, когда строка с ошибкой действительно выполняется.

Интерпретатор исполняет файл .py, не превращая его в машинный код. Что из перечисленного содержит машинный код?

  • а) интерпретатор Python
  • б) вывод программы на экране
  • в) файл с исходным кодом Python
  • г) документ текстового процессора

Интерпретатор тоже программа: он написан на языке C и скомпилирован в машинный код. Файл .py остается текстом, поэтому вариант «в» выбирают те, кто считает файл с исходным кодом программой для процессора. Вывод на экране и документ текстового процессора тоже данные, а не команды: вариант «б» путает программу с результатом ее работы.

Что именно установлено на компьютере

Слово «Python» означает три разные вещи: язык (общие правила), реализацию CPython (интерпретатор, написанный на C) и конкретную версию на вашем компьютере. Код выполняет именно версия на вашей машине. В курсе нужен Python 3.11 или новее. Версию показывает команда в терминале: на macOS и Linux python3 --version, на Windows python --version.

Python работает в двух режимах. В интерактивном режиме (REPL, цикл «чтение, вычисление, вывод») строка выполняется сразу после ввода, но ничего не сохраняется. Файл-скрипт с расширением .py можно сохранить, запустить снова и показать другим: все, что вы сдаете, пишется в файлах. Правило простое: эксперимент в REPL, результат в файле.

Редакторы на этой странице работают как маленькие файлы. Запустите пример кнопкой или сочетанием Ctrl+Enter, затем замените текст в кавычках и запустите снова.

От файла до результата

CPython сначала разбирает весь файл целиком, затем переводит его в байт-код и выполняет байт-код на своей виртуальной машине. Байт-код состоит из внутренних команд Python, а не из машинного кода процессора.

Из этого порядка следует, когда какая ошибка себя покажет.

Первые две ошибки Python найдет за вас. Третью найдете только вы, сравнив результат с ожидаемым.

Байт-код импортируемых модулей CPython сохраняет в папку __pycache__ в файлы .pyc, чтобы при следующем запуске не разбирать их заново. Эту папку можно удалить: при запуске она появится снова.

Сообщение об ошибке читается снизу вверх. Последняя строка называет тип ошибки и причину, строка File …, line N показывает место, где ошибку обнаружили. Запустите пример: в нем пропущены кавычки, и Python принимает good за имя переменной.

Python указывает место, где ошибка обнаружена, а не место, где ее допустили. Причина часто стоит строкой-двумя выше. Сначала прочитайте последнюю строку, сформулируйте гипотезу и только потом меняйте код.

Экосистема Python и среда разработки

Python состоит из трех слоев. Ядро языка небольшое: числа, строки, списки, множества, словари. Стандартная библиотека уже установлена вместе с Python: модули sys, random, math, os и многие другие. Сторонние пакеты развиваются отдельно от языка, хранятся в каталоге PyPI (pypi.org) и ставятся вручную командой python3 -m pip install с именем пакета.

Модуль стандартной библиотеки подключается командой import без установки. Запустите пример.

Пакет Biopython для работы с биологическими последовательностями сторонний. Пока его не установили, импорт завершается ошибкой ModuleNotFoundError.

Вы скопировали пример из интернета, а он падает на первой строке import numpy с ModuleNotFoundError. В чем причина?

  • а) в примере синтаксическая ошибка
  • б) пример написан под Windows, а у вас macOS
  • в) у вас установлен Python 2
  • г) пакет numpy у вас не установлен

numpy сторонний пакет, его нет в стандартной библиотеке, и пока его не поставили через pip, импорт не находит модуль. Синтаксическая ошибка дала бы SyntaxError, а не ModuleNotFoundError: название ошибки уже ставит диагноз. Операционная система здесь ни при чем. Python 2 исключается самим названием ошибки: ModuleNotFoundError появился в Python 3.6, в Python 2 сообщение было бы ImportError.

В анализе биологических данных у каждого этапа есть свой пакет: requests скачивает данные из баз NCBI, UniProt и Ensembl, Biopython читает форматы FASTA и FASTQ, pandas работает с таблицами, NumPy с числами, matplotlib строит графики. Все это второй семестр. В первом семестре программы пишутся на чистом Python.

Кто прочитает ваш код чаще всех?

Подсказка: вспомните, что происходит с программой после первого запуска.

Чаще всех код читаете вы сами: при каждой отладке и доработке. Код читают чаще, чем пишут, поэтому оформлять его нужно по общему стилю, а не по личному вкусу.

PEP 8 — соглашение сообщества Python об оформлении кода.

PEP 8 требует четыре пробела на уровень отступа, строки до 79 символов и имена_с_подчеркиванием. Общий стиль можно применять автоматически: автоформатер black переписывает код по правилам, линтер pylint находит нарушения.

Редактор кода защищает от типовых ошибок новичка. Подсветка синтаксиса показывает опечатку в имени функции. Автозамена табуляции на четыре пробела не дает смешать табы и пробелы, а отступы в Python значимы. Вертикальная линейка на 79–80 символах показывает, где строка ушла за край. К первому практическому занятию выберите VS Code или PyCharm Community.

Файл с программой — обычный текст в кодировке UTF-8 с расширением .py. Текст после # до конца строки называется комментарием: интерпретатор его пропускает, он нужен человеку. Полезный комментарий объясняет, зачем написана строка, а не пересказывает ее.

v = 8  # присвоить 8 переменной v (бесполезно)
v = 8  # скорость в милях в час (полезно)

Чтобы запустить файл из терминала, нужны три шага: перейти в папку с файлом командой cd, убедиться, что файл там (dir на Windows, ls на macOS и Linux), и запустить его командой python hello_world.py (на macOS и Linux python3). Терминал всегда находится в какой-то папке, и команда запуска ищет файл именно в ней.

Ошибка «файл не найден» при запуске почти всегда означает, что не сделан первый шаг: терминал открыт не в той папке.

К практическому занятию 1 проверьте: Python 3.11 или новее, редактор с табуляцией в 4 пробела и линейкой на 80 символах, установленный Git и папку проекта с именем из строчных букв и подчеркиваний.

Переменные и ссылочная модель

Каждое значение в Python имеет тип, и тип определяет, что со значением можно делать. Числа складываются, строки склеиваются, а поделить строку на число нельзя. Тип значения возвращает функция type().

Запустите пример, затем замените 17 на '17' в кавычках.

Кавычки служат признаком строки: 17 и '17' разные значения разных типов.

Знак = в Python означает присваивание, а не равенство. В строке x = x - 1 сначала вычисляется правая часть, затем имя слева привязывается к результату. Порядок исполнения обратен порядку чтения.

Создали список a = [1, 2, 3], затем написали b = a. Сколько списков теперь в памяти?

Подсказка: квадратные скобки создают список, подробно о списках будет в лекции 5. Подумайте, копирует ли b = a что-нибудь.

Список один. Если вы ответили «два», вы пользуетесь моделью «переменная как коробка», в которой у каждого имени своя копия значения. Python устроен иначе, и следующий абзац объясняет как.

Переменная — имя, привязанное к объекту; у одного объекта может быть несколько имен.

Удобнее представлять имя не коробкой со значением внутри, а ярлыком на объекте. Присваивание прикрепляет ярлык и ничего не копирует. После b = a в памяти остается один список с двумя ярлыками. Метод append() дописывает элемент в конец списка: изменили список через a, увидели изменение через b.

Оператор == сравнивает значения, а is проверяет, один ли это объект. Запустите пример и сравните две пары имен.

У каждого объекта есть тождество, которое не меняется за всю его жизнь. Функция id() возвращает его числом, оператор is его сравнивает. Чаще всего is нужен для проверки x is None: значение None означает «значения нет», и такой объект в программе один. Функция id() полезна при отладке, когда нужно понять, один это объект или два.

Два имени опасны только у изменяемого объекта. Список можно поменять на месте: b[0] = 17 кладет 17 на место номер 0, первое в списке. Строку изменить нельзя: b[0] = 'B' для строки дает TypeError, поэтому и сюрприза с двумя именами нет.

Только что список изменили через одно имя и увидели изменение через другое. Что напечатает программа?

a = [1, 2, 3]
b = a
b[0] = 17
print(a)
  • а) [1, 2, 3]
  • б) [17]
  • в) [17, 2, 3]
  • г) ошибку: a не менялась

Объект один, b[0] = 17 меняет его, поэтому print(a) показывает [17, 2, 3]. Ярлыки равноправны: неважно, через какой меняли и через какой смотрят. Ответ [1, 2, 3] дает модель коробок, ответ [17] получается, если считать, что b[0] = 17 заменяет весь список.

Имя переменной не может начинаться с цифры, содержать пробел или символы вроде @ и не может совпадать с одним из 35 ключевых слов (class, for, if, None и другие). Все такие ошибки дают SyntaxError. Регистр важен: LaTeX и latex разные имена.

Для интерпретатора имена не важны: программы с именами a, b, c и hours, rate, pay одинаковы. Для человека понятное (мнемоническое) имя напоминает, зачем переменная заведена.

hours = 35.0
rate = 12.50
pay = hours * rate
print(pay)

Встроенные типы и арифметика

Выражение — сочетание значений (операндов) и операторов, которое вычисляется в одно значение.

Выражение 2 + 3 * 4 сворачивается по шагам: сначала 2 + 12, затем 14. Порядок шагов задают правила приоритета, а не порядок чтения.

Одно и то же число можно записать по-разному: 42, 0b101010 (двоичная запись), 0o52 (восьмеричная), 0x2a (шестнадцатеричная). Подчеркивание помогает читать длинные числа: 123_456_789 хранится как 123456789. Форма записи принадлежит исходному тексту, а не числу.

Запятая не разделяет разряды. Python видит в print(1,000,000) три значения и печатает 1 0 0.

ОператорДействиеПример

Операторы // и % работают парой: целая часть и остаток вместе восстанавливают исходное число. Запустите пример, затем замените 105 на 200.

В Python 3 оператор / всегда дает float, даже при делении нацело: 4 / 2 дает 2.0. Целую часть дает только //. Достаточно одного float в выражении, чтобы результат стал float: 1 + 2.0 дает 3.0.

Приоритет операторов убывает от скобок к сложению: сначала ( ), затем **, затем *, /, //, % и последними + и -. При равном приоритете вычисление идет слева направо. Ответьте сами, затем нажимайте «Дальше».

ЛовушкаКажетсяНа самом деле

Степень выполняется раньше сложения, умножение раньше вычитания, а два вычитания идут слева направо. Исключение из правила «слева направо» одно: степень вычисляется справа налево, поэтому 2 ** 3 ** 2 дает 512, а не 64.

Если задумались о приоритете дольше секунды, ставьте скобки: они меняют порядок и делают его очевидным читателю.

Сколько будет 0.2 + 0.1?

Подсказка: запомните свой ответ и проверьте его в редакторе ниже.

Школьный ответ 0.3, а Python печатает 0.30000000000000004. Причина в том, как устроен тип float.

Тип float хранит число в 64 битах по стандарту IEEE 754, из них 53 бита отведены под значащие цифры. Число 1/3 нельзя точно записать десятичной дробью: 0.333… никогда не кончается. Так же число 1/10 в двоичной записи превращается в бесконечную периодическую дробь, а места есть только под 53 бита. Большинство десятичных дробей в float хранится приближенно, и так ведут себя C, Java, Fortran и другие языки.

Запустите пример: выражения похожи, а результаты отличаются.

По виду выражения нельзя предсказать, даст ли float ожидаемый результат. Даже перестановка множителей меняет последнюю цифру: 5 / 3 * 0.1 дает 0.16666666666666669, а 0.1 * 5 / 3 дает 0.16666666666666666. Поэтому сравнение вещественных чисел через == ненадежно.

Только что вы видели, что 3 * 0.1 дает 0.30000000000000004. Что напечатает программа?

print(0.1 * 3 == 0.3)
  • а) True
  • б) False
  • в) 0.3
  • г) 0.30000000000000004

0.1 * 3 дает 0.30000000000000004, это не 0.3, поэтому == возвращает False. Ответ True дает школьная арифметика. Ответы 0.3 и 0.30000000000000004 упускают, что результат сравнения логическое значение, а не число.

СитуацияИнструментКак

Допуск задается явно: math.isclose(a, b, rel_tol=0.05) разрешает разницу в 5 %. Сравнение с нулем особое: math.isclose(x, 0) без параметра abs_tol дает False для любого ненулевого x. Decimal создают из строки: Decimal(1.45) унаследует неточность float.

Тип bool имеет ровно два значения, True и False, и это не строки. В условии любое значение считается истиной или ложью: ложью считаются False, 0, 0.0, пустая строка '', пустой список [] и None, истиной все остальное. Функция bool() показывает, чем значение считается.

Смысл оператора определяют типы операндов. Для чисел + складывает, для строк склеивает: '100' + '150' дает '100150'. Строка, умноженная на целое число, повторяется: 'Test ' * 3 дает 'Test Test Test '. Сочетания 'Hello' + 3, 'Hello' * 3.0 и 'Hello' / 5 дают TypeError.

Кавычки в коде только прямые. Обратная кавычка и «елочки», скопированные из Word, дают SyntaxError.

Python никогда сам не истолковывает содержимое строки как число. Переход между типами пишется явно: int(), float(), str(). Запустите пример и обратите внимание на int(42.9): дробная часть отбрасывается, округления нет.

Операция над значением может закончиться тремя исходами. Если все сходится, int('126') / 3 дает 42.0. Если тип верный, а содержимое негодное, int('hello') дает ValueError. Если тип вообще не тот, '126' / 3 дает TypeError. Название ошибки уже ставит диагноз.

Ввод и вывод

Функция print() принимает любое число значений, печатает их через разделитель sep (по умолчанию пробел) и заканчивает строку значением end (по умолчанию перевод строки). Запустите пример, затем замените sep='-' на sep=''.

Вторая строка разгадывает загадку из прошлого раздела: print(1,000,000) получил три значения и напечатал их через пробел.

f-строка — строка с буквой f перед кавычками, в которой выражение в фигурных скобках заменяется своим значением.

Склейка 'I am number ' + 42 дает TypeError, а 'I am number ' + str(42) работает, но громоздко. f-строка подставляет значение без ручного преобразования, а после двоеточия в скобках можно задать формат.

Функция input() печатает приглашение и останавливает программу, пока человек не наберет текст и не нажмет Enter. Затем она возвращает набранную строку. Символ \n в конце приглашения переводит строку, чтобы ввод оказался под вопросом. В редакторах этого сайта ввод задается заранее в поле «Ввод».

input() без текста-приглашения делает программу плохой, даже если она работает: человек не знает, что вводить, и программа кажется зависшей.

Подсказка: с клавиатуры приходят символы.

Программа получила текст из двух символов, строку '17'. Функция input() всегда возвращает строку, даже если набраны одни цифры.

Для арифметики ввод нужно преобразовать, и лучше сразу при вводе: потом легко забыть, откуда пришло значение. Запустите пример, затем уберите int() и запустите снова.

Биологические данные в программе

Специального «биологического» типа в Python нет, и он не нужен. Нуклеотидная или белковая последовательность, идентификатор и описание записи хранятся строками str. Значит, к последовательности применимо все, что известно о строках: len(), индексы, срезы и методы из лекции 2.

Алфавит ДНК: A, T, C, G (аденин, тимин, цитозин, гуанин). Буква N обозначает неопределенный нуклеотид, строчные буквы обычно отмечают замаскированные повторы.

ВеличинаТипПочему

GC-составfloatдоля, не целое

Длина всегда целая. Если длина получилась float, где-то в расчете стоит деление через /.

Запись FASTA — строка описания, начинающаяся с >, и следующие за ней строки последовательности.

>gene_00284728 length=231;type=dna
GAGAACTGATTCTGTTACCGCAGGGCATTCGG

Идентификатор идет сразу после > до первого пробела. Все после первого пробела относится к описанию, а описания может не быть вовсе, тогда это None. Последовательность продолжается до следующего > или до конца файла. Типичные ошибки разбора: лишний пробел после > и повторяющиеся идентификаторы.

Строка описания: >gene_1 length=231. Что программа должна взять как идентификатор?

  • а) gene_1
  • б) >gene_1
  • в) gene_1 length=231
  • г) length=231

Знак > только отмечает строку описания, а идентификатор идет после него до первого пробела. Ответ >gene_1 дают те, кто берет строку до пробела целиком вместе со скобкой. Ответ gene_1 length=231 дают те, кто считает идентификатором всю строку. length=231 относится к описанию.

Считаем gc = (g + c) / n * 100 и отбираем записи с GC-составом ровно 55 %. Что может пойти не так?

Подсказка: вспомните раздел о вещественных числах.

GC-состав получается делением, значит, это float, а сравнение float через == ненадежно. Запись с GC-составом 55 % может не пройти проверку gc == 55.

GC-состав — доля гуанина и цитозина среди всех нуклеотидов последовательности, обычно в процентах.

Доля означает float, а float означает, что == ненадежно. В последовательности из 20 нуклеотидов 6 гуанинов и 5 цитозинов: GC-состав ровно 55 %, а программа считает иначе. Запустите пример.

Вычисленный GC-состав сравнивают с допуском через math.isclose(), округляют только при выводе, а записи фильтруют по порогу через > и <, а не через ==.

GC-состав бывает равен нулю, а math.isclose(gc, 0.0) без параметра abs_tol дает False для любого ненулевого gc.

Риск двух имен зависит от изменяемости, а не от того, что данные биологические. Одна последовательность хранится строкой, строка неизменяема, и два имени на ней безопасны. Набор последовательностей хранится списком, список изменяем, и два имени на одном наборе становятся источником тихих ошибок.

Практические занятия семестра последовательно развивают одну программу: проверка входных данных, разбор файла FASTA, статистики и GC-состав, частоты нуклеотидов, поиск мотивов, фильтрация и отчет. Типы, переменные, ввод и вывод из этой лекции нужны на каждом этапе.

Чем интерпретатор отличается от компилятора?

  • Интерпретатор переводит программу целиком и сохраняет файл с машинным кодом
  • Интерпретатор исполняет программу сам и файла с машинным кодом не создает
  • Интерпретатор работает только в интерактивном режиме
  • Интерпретатор не находит синтаксических ошибок

Файл с машинным кодом создает компилятор. Интерпретатор исполняет программу по ходу и умеет работать как с отдельными строками в REPL, так и с файлом. Синтаксические ошибки CPython находит при разборе файла.

В пятой строке программы из десяти строк забыта закрывающая скобка. Что увидит студент при запуске?

  • Выполнятся первые четыре строки, затем появится SyntaxError
  • Программа выполнится, но пятая строка будет пропущена
  • SyntaxError, и не выполнится ни одна строка
  • Программа отработает без сообщений, но результат будет неверным

Python разбирает весь файл до выполнения, поэтому синтаксическая ошибка обнаруживается раньше первой строки. Первый вариант описывает ошибку времени выполнения, последний описывает семантическую ошибку.

Команда запуска ищет файл в папке, в которой находится терминал. Синтаксическая ошибка и неверная кодировка дали бы SyntaxError, а без Python не нашлась бы сама команда python3.

Как надежно проверить, что вычисленное значение x равно 0,7?

  • x == 0.7
  • math.isclose(x, 0.7)
  • x is 0.7
  • str(x) == '0.7'

float хранит большинство десятичных дробей приближенно, поэтому вычисленное число может отличаться в последней цифре. math.isclose() сравнивает с допуском. == и сравнение строк чувствительны к этой цифре, а is проверяет тождество объектов, а не значение.

В последовательности 40 нуклеотидов, из них 9 гуанинов и 13 цитозинов. Какое выражение дает GC-состав в процентах?

  • (9 + 13) // 40 * 100
  • 9 + 13 / 40 * 100
  • (9 + 13) / 40 * 100
  • (9 + 13) % 40 * 100

GC-состав — доля, поэтому нужно деление /, а скобки заставляют сначала сложить: получается 55 %. Без скобок деление выполняется раньше сложения. // отбросит дробную часть и даст 0, а % дает остаток, а не долю.
