Логика и ветвления

Как программа принимает решения: логический тип, сравнения, логические операторы, ветвление if/elif/else, истинность значений и None.

После лекции вы сможете

  • записывать условия сравнениями и операторами and, or, not, in и предсказывать их значение;
  • выбирать выполняемый код инструкциями if, elif, else и проверять, в какую ветвь попадут граничные значения;
  • проверять истинность значений и None и записывать проверку заголовка FASTA плоской цепочкой условий.

Тип bool и сравнения

Как записать в программе ответ «да» или «нет»?

Подсказка: какие типы данных мы уже знаем?

Можно взять строку "да" или число 1, но тогда легко ошибиться в написании или перепутать значения. Для ответа «да» или «нет» в Python есть отдельный тип с двумя значениями, bool.

До сих пор программы выполнялись сверху вниз, строка за строкой, и при любых данных одинаково. Настоящая программа постоянно принимает решения: перед ней заголовок или строка последовательности, допустима ли буква, не пуста ли строка. Чтобы принять решение, программа задает данным вопрос и получает ответ «да» или «нет».

Логическое значение — ответ «да» или «нет». В Python у него отдельный тип bool и ровно два значения: True и False.

Значения пишутся без кавычек и с прописной буквы. Слово true Python не узнает, а "True" в кавычках уже обычная строка из четырех букв. В арифметике True ведет себя как 1, а False как 0. Запустите пример, затем замените True + 1 на True + True и запустите снова.

Тип bool появился в Python 2.3 (PEP 285) и устроен как частный случай целого числа, поэтому isinstance(True, int) дает True. До него ответ «да» или «нет» хранили числами 0 и 1. Отдельный тип удобнее: True в коде сразу говорит читателю, что это ответ на вопрос, а не количество.

Сложение логических значений позволяет посчитать, сколько условий выполнено: сумма нескольких сравнений равна числу истинных. Например, (5 > 3) + (2 > 3) + (1 == 1) дает 2.

Что выведет print(True + True)?

  • а) True
  • б) TypeError
  • в) "TrueTrue"
  • г) 2

В арифметике True равно 1, поэтому сумма двух True дает целое число 2, а не логическое значение. True выбирают, если считают + логическим «или», а TypeError, если думают, что bool нельзя складывать. "TrueTrue" получилось бы только у строк: "True" + "True".

Сравнение дает True или False

Любое сравнение дает значение типа bool. Вопрос «не длиннее ли строка 80 символов» Python записывает как len(seq) <= 80: NCBI рекомендует строки последовательности в файле FASTA не длиннее 80 символов. Равенство проверяют два знака ==. Сравнение строк учитывает регистр, поэтому те же буквы в нижнем регистре уже не равны.

Шесть операторов сравнения знакомы по математике, отличается только запись. «Не равно» пишется как !=, «меньше или равно» как <=: два символа без пробела, знак равенства второй. Операторов =< и => в Python нет.

Условие чаще всего стоит после слова if: строка с отступом под ним выполняется, только если условие истинно. Подробно инструкция if разобрана в разделе 3, а здесь она нужна, чтобы показать самую частую ошибку первых недель.

Один знак = присваивает значение переменной, два знака == сравнивают и отвечают True или False. Присваивание на месте условия дает SyntaxError. Python находит такую ошибку до запуска, поэтому в примере ниже не выполнится даже первая, правильная проверка.

Прочитайте последнюю строку сообщения: интерпретатор подсказывает, что вы, вероятно, имели в виду ==. Оператор := из той же подсказки устроен иначе, в этой лекции он не нужен.

Сравнение строк и разных типов

Строки Python сравнивает как слова в словаре: первый символ с первым, при совпадении второй со вторым, до первого различия. Поэтому "GC" < "GT": первые буквы равны, а C меньше T. «Меньше» здесь означает меньший номер символа в таблице Unicode, а не место в алфавите. Все прописные латинские буквы стоят в этой таблице раньше строчных, поэтому любая прописная буква меньше любой строчной.

Когда регистр не важен, обе строки приводят к одному регистру методом upper() или lower(). Числа разных типов сравниваются по значению: 2 == 2.0 истинно. Строка и число просто не равны, а спросить, какое из них меньше, нельзя: программа останавливается с ошибкой TypeError. Запустите пример: шесть строк напечатаются, на седьмой программа остановится.

Посимвольное сравнение касается и цифр в строках. Строки из цифр упорядочены не как числа: "10" < "9" истинно, потому что первый символ "1" меньше "9".

Функция input() всегда возвращает строку. Сравнение такой строки с числом дает False вместо равенства или TypeError при сравнении на порядок. Строку сначала переводят в число: int(input()) == 5.

Номер символа показывает функция ord() из лекции о строках: ord("A") дает 65, ord("B") дает 66, ord("a") дает 97. Документация насчитывает восемь операций сравнения: к шести из таблицы добавляются is и is not, которые сравнивают не значения (раздел 4).

Что выведет print("a" < "B")?

  • а) True
  • б) False
  • в) None
  • г) TypeError

Python сравнивает номера символов: у строчной a номер 97, у прописной B 66. Прописные буквы идут раньше строчных, поэтому ответ False. True получается при сравнении по алфавиту без учета регистра, а TypeError бывает при сравнении строки с числом на порядок. None сравнение не дает никогда: его результат всегда bool.

Логические операторы

Последовательность длиннее 100 букв и без N: как проверить оба условия сразу?

Подсказка: как бы вы сказали это по-русски?

По-русски условия соединяет союз «и»: длиннее 100 букв и без N. В Python для этого есть логический оператор and, а также or и not.

Одно сравнение отвечает на один вопрос, а в реальной проверке вопросов обычно несколько. Например, для анализа нужны последовательности длиннее 100 букв и без буквы N, которая обозначает неизвестный нуклеотид. Каждое условие мы уже умеем записать отдельно. Осталось соединить их так же, как соединяет их союз «и» в речи.

Логические операторы and, or и not соединяют условия в одно. and истинно, когда истинны обе части, or — когда истинна хотя бы одна, not меняет истину на ложь и обратно.

Логическое «или» не исключающее. На вопрос «чай или кофе» в кафе ждут что-то одно, а or истинно и тогда, когда верны обе части. Каждая часть остается полным условием: len(seq) > 100 and seq.count("N") == 0.

aba and ba or bnot a
TrueTrueTrueTrueFalse
TrueFalseFalseTrueFalse
FalseTrueFalseTrueTrue
FalseFalseFalseFalseTrue

У and единственная строка с True та, где истинны обе части. У or единственная строка с False та, где обе части ложны. Таблицу не нужно заучивать: ее восстанавливают по смыслу союзов «и», «или», «не».

Результат сравнения можно сохранить в переменную с именем-вопросом и собирать условие из таких имен почти как фразу: «длинная и не содержит N». Запустите пример, затем замените последовательность на "ATGCGGGTAC" и запустите снова.

Для исходной последовательности обе переменные равны True: букв 10, и N в строке есть. not has_n дает False, поэтому and дает False. Для or хватает одной истинной части.

Порядок вычисления

В арифметике умножение выполняется раньше сложения, и у логических операторов тоже есть порядок. Сначала вычисляются сравнения, затем not, потом and, последним or. Поэтому not a == b означает not (a == b), а a or b and c означает a or (b and c). Если сомневаетесь в порядке, поставьте скобки: в условиях они не лишние.

Аналогия с арифметикой такая: and похоже на умножение, or на сложение. Полная таблица приоритетов приведена в справочнике языка, The Python Language Reference, раздел 6.17. Знаки & и | похожи на and и or, но это побитовые операторы с другим приоритетом: при a = 10 выражение a <= 10 & 1 < a дает False. В условиях пишите and и or.

Цепочка сравнений

Сравнения, стоящие подряд, Python соединяет в цепочку. Запись 0.4 < gc < 0.6 читается как в математике и означает 0.4 < gc and gc < 0.6. В цепочку встает любое сравнение, в том числе ==, потому что у всех сравнений один приоритет. Строка gc > 0.4 == True поэтому спрашивает, больше ли gc чем 0,4 и равно ли 0,4 значению True. Вторая пара ложна. Другой порядок задают скобки. Пример ниже сначала показывает порядок логических операторов, затем цепочки.

В цепочке средняя часть вычисляется один раз, а при ложной первой паре остальные пары не проверяются. Цепочки вроде 1 < x > 3 или a == b == c допустимы, но читаются плохо; пишите только a < x < b и a <= x <= b. С True через == в настоящих условиях не сравнивают (раздел 4): здесь сравнение показывает только устройство цепочки.

Ловушка «равно A или C»

По-русски «буква равна A или C» звучит естественно, и так же хочется написать в программе: base == "A" or "C". Python разбирает эту строку по правилам приоритета как (base == "A") or "C". Непустая строка "C" в условии считается истиной (почему, объясняет раздел 4). В итоге условие выполняется для любой буквы.

Такая ошибка не дает никакого сообщения: программа работает, но неверно. Оператор or соединяет целые выражения, а не варианты значения, поэтому сравнение пишут полностью в каждой части: base == "A" or base == "C".

Проверка вхождения in

Оператор in спрашивает «входит ли». Для строк это значит «встречается ли такой кусок подряд». not in задает обратный вопрос: x not in s то же, что not (x in s). Допустимые буквы удобно хранить строкой и спрашивать base in "ACGT". В РНК вместо T стоит урацил U, поэтому "U" not in seq отвечает на вопрос «это ДНК, а не РНК?».

Для строк in ищет подстроку, а не одну букву из набора. Проверка base in "ACGT" надежна, только если base ровно одна буква: строки "AC" и "" тоже ее проходят. Надежная запись: len(base) == 1 and base in "ACGT".

Сокращенное вычисление

Сокращенное вычисление (short-circuit evaluation) — правило, по которому and и or вычисляют правую часть, только если без нее ответ неизвестен.

Если левая часть and ложна, все выражение уже ложно, и правая часть не вычисляется. Если левая часть or истинна, ответ уже True. Это видно на делении на ноль: 10 / x при x = 0 останавливает программу ошибкой. Запустите пример: две первые проверки отвечают по левой части, а в третьей деление стоит слева и выполняется первым.

Сокращенная запись делает то же, что полная запись через if и else из раздела 3. Для первой проверки полная запись выглядит так:

if x != 0:
    print(10 / x > 1)
else:
    print(False)

Python делит, только если левая часть истинна, а иначе сразу печатает False. У умножения, с которым сравнивали and, такого правила нет: на этом аналогия с арифметикой заканчивается.

Безопасная проверка ставится слева

Сокращенное вычисление защищает от ошибки. В реальных данных бывают пустые строки, и обращение seq[0] к пустой строке дает IndexError. Если слева поставить проверку длины, до опасного обращения дело не дойдет: для пустой строки получится False, для заголовка True. Такое условие называют охранником (guardian pattern), и оно всегда стоит слева от опасной части.

Что выведет программа seq = "", print(seq[0] == ">" and len(seq) > 0)?

  • а) True
  • б) False
  • в) IndexError
  • г) SyntaxError

and вычисляется слева направо, и первым идет обращение к символу пустой строки: IndexError. Охранник стоит справа и ни от чего не защищает. False получилось бы, если поменять части местами. SyntaxError означает ошибку записи, а здесь запись правильная и ошибка возникает при выполнении.

if, elif, else

Как сделать, чтобы строка кода выполнялась не всегда?

Подсказка: файл FASTA состоит из строк двух видов.

Строку кода нужно поставить под условие: выполнять ее, только если условие истинно. Для заголовков FASTA одно действие, для строк последовательности другое. Это делает инструкция if.

Условия мы писать научились, теперь программа будет действовать по ним. В файле FASTA есть строки двух видов: заголовки, которые начинаются со знака >, и строки с нуклеотидами. С заголовком нужно сделать одно, с последовательностью другое, поэтому часть кода должна выполняться не всегда.

Ветвление — выбор по значению условия, какой код выполнить. Условием называют логическое выражение после if, а ветвью блок, который выполняется при одном из ответов.

Инструкция if без else выполняет блок, если условие истинно, и пропускает его, если ложно. С else выполняется ровно одна из двух ветвей: условие не может быть одновременно истинным и ложным. В обоих случаях после инструкции программа продолжается одинаково.

В примере ниже условие задает метод startswith(): он возвращает True или False, и этого достаточно. В ветви if две строки, а ветвь else пропущена целиком. Последняя строка стоит без отступа, не принадлежит ни одной ветви и выполняется в любом случае. Запустите пример, затем замените строку на "ATGCGT".

Метод startswith() безопасен и для пустой строки, в отличие от line[0]: для "" он просто вернет False.

Блок и отступ

Во многих языках ветвь заключают в фигурные скобки, а в Python ее границы задает отступ. Двоеточие в конце строки if говорит, что дальше будет блок. Отступ, обычно в четыре пробела, показывает, какие строки в него входят. Блок кончается там, где кончается отступ: сдвиньте строку влево, и она окажется вне ветви.

Без отступа после двоеточия Python сообщает IndentationError. Та же ошибка возникает при лишнем пробеле перед строкой. Запустите пример и прочитайте последнюю строку сообщения.

В блоке должна быть хотя бы одна инструкция. Если ветвь нужна, а написать в ней пока нечего, ставят pass, инструкцию, которая ничего не делает.

if line.startswith(">"):
    pass    # обработку заголовка напишем позже
else:
    print("нуклеотиды")

Настройте редактор так, чтобы клавиша Tab вставляла четыре пробела, и не смешивайте табуляцию с пробелами. На экране они выглядят одинаково, а для Python это разные отступы.

А если вариантов больше двух?

Подсказка: низкий, средний или высокий GC-состав.

if с else выбирает из двух вариантов. Для трех и больше между ними ставят ветви elif: условия проверяются сверху вниз до первого истинного.

Цепочка if, elif, else

Инструкция if с else выбирает из двух вариантов, но вариантов часто больше: у последовательности может быть низкая, средняя или высокая доля нуклеотидов G и C. Для этого служит цепочка if, elif, else. Слово elif означает «else if»: следующее условие проверяется, только если все предыдущие ложны.

Цепочка elif — инструкция, в которой условия проверяются сверху вниз и выполняется только первая истинная ветвь, даже если истинны несколько.

Как только условие истинно, выполняется его ветвь, и на этом вся инструкция заканчивается: остальные условия даже не вычисляются. else срабатывает, если ложны все условия. Число elif не ограничено, а else можно не писать; тогда при всех ложных условиях не выполнится ничего.

В примере доля G и C равна 0,6: шесть букв из десяти. Пороги 0,4 и 0,6 учебные, это не биологическая норма. Во втором условии не нужно писать gc >= 0.4: программа доходит до него, только если первое условие уже ложно. Значение ровно 0,6 не меньше 0,6, поэтому вторая ветвь пропущена и сработал else. Запустите пример, затем замените во втором условии < на <= и посмотрите, куда попадет граница.

Проверяя цепочку, подставьте значение из каждой группы и каждое граничное значение: так видно, в какую ветвь оно попадет.

Цепочка останавливается на первом истинном условии. Если широкое условие стоит раньше узкого, узкая ветвь не выполнится никогда. В примере ниже при gc = 0.7 истинны оба условия, но программа печатает «средний»: любое число больше 0,6 больше и 0,3. Python об этом не предупредит, код синтаксически правильный. Узкое условие ставят раньше широкого или записывают условия так, чтобы они не пересекались.

Что выведет программа при gc = 0.7?

gc = 0.7
if gc > 0.6:
    print("высокий")
if gc > 0.3:
    print("средний")
  • а) высокий
  • б) средний
  • в) ничего
  • г) высокий и средний

Здесь две независимые инструкции if, а не цепочка: каждая проверяет свое условие. При gc = 0.7 оба условия истинны, поэтому напечатаны оба слова. Только «высокий» напечатала бы цепочка elif, а «средний» получился в ловушке выше, где широкое условие стояло первым. Если должна сработать одна ветвь из нескольких, пишут цепочку elif; если проверки независимы, пишут серию if.

Истинность и None

Можно ли написать if seq:, когда seq строка?

Подсказка: вспомните ловушку с or "C".

Можно. В ловушке base == "A" or "C" строка "C" уже сработала как условие. У каждого значения есть истинность: непустая строка считается истиной, пустая ложью.

До сих пор в условиях стояли сравнения. Но в ловушке base == "A" or "C" условием сработала просто строка "C", и Python ее принял. Значит, проверить на истинность можно любое значение, а не одни True и False.

Истинность значения — то, чем оно считается в условии: истиной или ложью. Ее показывает функция bool(), а в if Python вызывает ее сам.

Правило короткое: ложны ноль и пустота, все остальное истинно. К нулю относятся 0 и 0.0, к пустоте None, пустая строка и пустые коллекции. Коллекции появятся в следующих лекциях, правило для них то же. Строка ложна, только если в ней нет ни одного символа. Запустите пример, затем замените seq на пустую строку.

Раз пустая строка ложна, проверку «есть ли что-нибудь в строке» записывают одним словом. Логическую переменную тоже не сравнивают с True: is_long уже равна True или False, и вопрос «правда ли, что правда» лишний. Так рекомендует руководство по оформлению кода PEP 8.

PEP 285 объясняет, почему с True не сравнивают через ==: если бы любое истинное значение было равно True, то из 6 == True == 7 следовало бы ложное 6 == 7. Полный список ложных значений в документации длиннее таблицы: в него входят, например, пустые списки и словари, которые появятся позже.

or и and возвращают операнд

Теперь видно, почему сработала ловушка с or "C". Операторы and и or не превращают результат в True или False, а возвращают одно из своих значений, то, на котором остановилось вычисление. x or y дает x, если x истинно, иначе y. x and y устроен зеркально: дает x, если x ложно, иначе y.

На or строится значение по умолчанию: seq_id or "без имени" дает идентификатор, а если он пустой, запасную строку. В 0 and 5 левый ноль ложен, выражение уже ложно, и and возвращает этот ноль. В 0 or 5 левый ноль ложен, но для or это еще не ответ, и возвращается 5.

Общее правило: a or b дает первое истинное значение или последнее, a and b дает первое ложное или последнее. Прием с or заменит и законный ноль: 0 or 5 дает 5, даже если 0 был настоящим результатом. Сложную логику на and и or не строят, для нее пишут if.

Как записать «значения пока нет»?

Подсказка: пустая строка уже означает «строка есть, но пустая».

Ноль и пустая строка сами бывают настоящими значениями. Для «значения нет» в Python есть отдельный объект None.

Значение None

Пусть GC-состав еще не посчитан. Записать 0 нельзя: ноль бывает настоящим ответом. Пустая строка тоже значение, просто пустое. Нужно значение, которое означает именно «пока ничего нет».

None — специальный объект, который означает «значения нет». Это единственный объект типа NoneType: второго None в программе не бывает.

Пустая строка — настоящая строка с типом str и длиной 0, а None значит, что строки нет вообще. Поэтому None == "" и None == 0 дают False, хотя в условии все три значения ложны. None возвращает функция, которая ничего не возвращает явно, например print(): она печатает, но результата не отдает.

В биоинформатике None встречается сразу. Функция readfq из книги «Bioinformatics Data Skills» (V. Buffalo) читает записи FASTA и FASTQ и для каждой возвращает строку качества прочтения. У записи FASTA качества нет, и вместо него приходит None. Вызов len(None) дает TypeError: у отсутствующего значения нет длины.

== и is

Оператор == отвечает на вопрос «равны ли значения», а is на вопрос «один ли это объект». Равные значения не обязаны быть одним объектом, как два близнеца не один человек. Все переменные со значением None ссылаются на один и тот же объект, поэтому None проверяют через is: x is None и x is not None. В остальных случаях сравнивают через ==.

С небольшими целыми числами is иногда дает True, потому что CPython хранит числа от −5 до 256 в одном экземпляре. Полагаться на это нельзя: числа и строки сравнивают через ==.

Проверка if not x не отличает отсутствие значения от нуля и пустой строки: для not значения None, 0.0 и "" одинаково ложны. У последовательности из одних A и T GC-состав равен нулю, и это честный ответ. Первая проверка в примере принимает его за отсутствие результата, вторая спрашивает ровно то, что нужно.

Какое из значений Python считает ложным?

  • а) 0.0
  • б) "0"
  • в) " "
  • г) "False"

Ложны ноль и пустота, поэтому ложно только 0.0. Строка ложна, только если она пустая, а в "0", " " и "False" есть символы. Пробел тоже символ, а "False" в кавычках строка, а не значение False. Поэтому введенный через input() текст "0" в условии окажется истиной.

Как выпрямить лесенку

Четыре приема делают проверку плоской.

  • Вложенные if без else заменяют одним условием с and.
  • Двойное сравнение 1 <= n and n <= 25 записывают цепочкой 1 <= n <= 25.
  • Ошибки проверяют первыми ветвями цепочки, а нормальный случай оставляют в else.
  • Выбор из двух значений записывают условным выражением.

Ниже та же проверка цепочкой elif. Условия перевернулись: вместо «начинается с >» стоит «не начинается», потому что каждая ветвь описывает ошибку и тут же сообщает о ней. Проверку читают сверху вниз, как список требований. Цепочка 1 <= len(sid) <= 25 заодно исправляет ошибку лесенки: пустой идентификатор теперь не проходит. Запустите пример с заголовками ">Seq1", ">" и "Seq1".

Запись not 1 <= len(sid) <= 25 читается как not (1 <= len(sid) <= 25), потому что сравнения связывают сильнее not. По правилам NCBI после SeqID через пробел могут идти модификаторы вида [organism=…], и тогда SeqID занимает часть заголовка до первого пробела. Разрешенные символы SeqID (буквы, цифры и несколько знаков) проверяют по одному, и для этого нужен цикл.

Условное выражение

Условное выражение a if условие else b дает a, если условие истинно, и b, если ложно. Им записывают выбор одного из двух значений.

Прежде чем проверять буквы последовательности, нужно договориться, какие буквы допустимы. Для этого есть стандартный код IUPAC. Итоги и типичные ошибки

  • Сравнение дает значение типа bool; строки сравниваются по номерам символов с учетом регистра.
  • Условие собирается из сравнений, in, and, or, not; порядок вычисления и порядок частей важны.
  • Сравнения подряд образуют цепочку: a < b < c означает a < b and b < c.
  • Цепочка elif выполняет первую истинную ветвь; узкое условие ставят раньше широкого.
  • Ложны ноль, пустота и None; отсутствие значения проверяют через is None.
  • Читаемая проверка плоская: сначала ошибки, затем нормальный случай в else.

Что выведет print("100" < "25", 100 < 25)?

  • TypeError

Строки сравниваются посимвольно: первый символ "1" меньше "2", поэтому "100" < "25" истинно, хотя число 100 больше 25. Числа сравниваются по значению, и 100 < 25 ложно. False False получается, если сравнивать строки как числа, а TypeError бывает только при сравнении строки с числом.

Что выведет print(n > 3 or n < 4 and n == 0) при n = 5?

  • False
  • True
  • 5
  • SyntaxError

and вычисляется раньше or, поэтому Python читает выражение как n > 3 or (n < 4 and n == 0). Левая часть or истинна, и ответ True. False получается, если вычислять слева направо: (n > 3 or n < 4) and n == 0. Обе части or здесь сравнения, поэтому результат логический, а не число 5.

Что выведет print(0 < n <= 10 != 5) при n = 5?

  • False
  • True
  • SyntaxError
  • TypeError

Сравнения подряд образуют цепочку: 0 < n and n <= 10 and 10 != 5. Последняя пара сравнивает 10 с 5, а не n с 5, поэтому все три части истинны. False выбирают те, кто читает != 5 как проверку n. Запись правильная, ошибок нет.
